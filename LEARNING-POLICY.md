# Learning and promotion policy

Each project owns its brief, decisions, source facts, feedback and review result. Shared brand/motion guidance changes only through explicit promotion of a durable preference.

For every proposed learning record: the exact feedback or evidence; project/asset reference; scope (brand-wide, format-specific or project-only); whether the user explicitly endorsed it or it is an agent inference; contradictory examples; and the proposed rule. Use templates/learning-record.md.

Examples:

- 'This shot's OCR correction is too fast' is project feedback. 'Give complete text time to be read' is an existing broad principle. A specific number of milliseconds is not established for all content.
- 'Frame C appearance approved' is shared style evidence. 'Case Map at second 33' is project timing.
- 'Reel V3 is the one I used' selects a successful example. It does not approve all music, typography, caption or camera decisions as future requirements.
- A failed render is an implementation issue, not a user preference.

Agents may record project feedback autonomously. Proposed changes to shared guidance remain labelled proposals until explicitly approved by the user or the current brief delegates that authority. Keep a dated decision history when promoting or superseding a rule; never silently overwrite a rejection. This file governs this repository's learning records, not any external assistant memory system.
